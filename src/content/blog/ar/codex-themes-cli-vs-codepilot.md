يقوم مستخدمي الأTerminal بتطبيق سمات Codex باستخدام الأوامر، وليس المعارض. تظهر هذان الاسمان باستمرار وهما **Codex Themes CLI** (من ychampion/codex-themes) و**Codepilot** (يمكن تثبيته عبر npm). يوفر كلاهما أمرًا مثل `/theme` أو `/skin` في الطرفية — لكنهما مصممان لمستخدمين مختلفين. إليك مقارنة صريحة.

## نظرة عامة

| | Codex Themes CLI | Codepilot |
|---|---|---|
| النوع | CLI خفيف | مدير TUI كامل |
| التثبيت | ملف script من curl / مستودع | npm |
| الأمر الأساسي | `/theme <الاسم>` | `/skin` |
| التحقق | أساسي | تحقق مدمج |
| التصحيح | لا يوجد تصحيح مرئي | دعم للتصحيح |
| التراجع | يدوي | تراجع مدمج |
| تصدير لون الطرفية | محدود | نعم |

## Codex Themes CLI: النمط البسيط

Codex Themes CLI هو الأسلوب الكلاسيكي: تقوم بتثبيت سمة وتغييرها باستخدام `/theme monokai-stone`. إنه تابع مباشر لعملية تخصيص السمات في VS Code / tmux — أمر واحد، سمة واحدة، بدون إطالة.

**المزايا:**
- **قابل للبرمجة.** أوامر `/theme` تناسب السكريبتات والمهام.
- **متوقع.** أمر واحد يؤدي شيء واحد؛ لا قائمة لاستكشافها.
- **خفيف.** لا يتم تثبيت أي شيء إضافي غير ملفات السمة.

**العيوب:**
- **لا يوجد تصحيح.** أنت تُسجل التغيير قبل أن تراه.
- **إدارة يدوية.** إزالة السمات أو تصحيحها على عاتقك.
- **تحقق محدود.** إذا كانت السمة معطوبة، ستفشل عند التطبيق، وليس عند التثبيت.

## Codepilot: الأداة القوية TUI

Codepilot هو مدير كامل لسمات الطرفية: واجهة TUI حيث يمكنك عرض السمات، التحقق منها، تصحيحها، تطبيقها، التراجع عنها، وتصدير ألوان الطرفية. إنها أكثر من "أداة تخصيص سمة تعيش في طرفيتك" من "أمر سمة".

**المزايا:**
- **التحقق قبل التطبيق.** يتم اكتشاف السمات المعطوبة مبكرًا.
- **التراجع المدمج.** إذا أخطأت في تطبيق سمة؟ ارجع بفريق واحد.
- **تصدير الألوان.** قم بإنشاء ألوان الطرفية والمحرر المتوافقة من سمة Codex — فائدة حقيقية لمحبي التنسيق.
- **الدعم عبر المنصات عبر npm."

**العيوب:**
- **أكثر تعقيدًا.** تثبيت أثقل، وفهم مفاهيم أكثر.
- **إفراط في التعقيد لمستخدمي السمة الواحدة.** إذا كنت تستخدم سمة واحدة مدى الحياة، فإن واجهة TUI قد تكون إطالة.

## أي منهما يناسبك؟

- **أنت تعيش في dotfiles وتريد أدوات بسيطة:** Codex Themes CLI. يناسب فلسفة Unix — أمر واحد، قابل للتجميع.
- **أنت تتعامل مع عدة سمات وتريد حماية:** Codepilot. التحقق والتراجع يستحقان التكلفة أول مرة تتعطل فيها سمة.
- **تريد ألوان طرفيتك ومحررك متوافقة:** Codepilot. ميزة التصدير هي الفارق.
- **أنت على جهاز مشترك/آلة CI:** Codex Themes CLI — قابل للبرمجة وخفيف على الاعتماد.

## سؤال الألوان

هذا هو الفصل الحقيقي. إذا كان توافق سمة Codex مع لون طرفيتك مهمًا لك، فإن تصدير Codepilot هو ميزة حقيقية — فإنه يولد ألوان الطرفية من سمة Codex بدلًا من أن تُدخل القيم اليدويًا. [Monokai Stone (CLI)](/skins/monokai-stone-cli/) أو [Solarized (CLI)](/skins/solarized-cli/) هما أمثلة جيدة لتجربتها، لأن الإصدارات التي تدعم CLI تُطبق بسلاسة عبر أي أداة.

## أسئلة شائعة

**هل يمكنني استخدام كلاهما؟**
نعم — إدارة السمات في التنسيقات المدعومة (ملفات CLI). فقط لا تعمل كليهما كتطبيق نشط في نفس الوقت.

**هل يدعم أي منهما ملفات tmtheme؟**
يتعامل كلاهما مع التنسيقات القياسية لـ CLI؛ دعم استيراد tmtheme يختلف. تحقق من وثائق المستودع الخاصة بملف السمة الخاص بك.

**أي منهما أفضل للمبتدئين في الطرفية؟**
Codepilot، بسبب التحقق والتصحيح. واجهة TUI توجهك؛ بينما CLI الخفيف يفترض أنك تعرف ما تفعله.

**هل تعمل هذه الأدوات على macOS وWindows؟**
Codex Themes CLI يغطي المنصات التي تدعمها إصداراته؛ أما Codepilot فهو قائم على npm ويدعم جميع المنصات.

إذا كنت ترغب في أداة خفيفة وقابلة للبرمجة، اختر Codex Themes CLI. إذا كنت ترغب في التحقق، التصحيح، وتصدير الألوان، اختر Codepilot. سواءً أكنت تختار أي منهما، قم بتوصيله بسمة CLI جيدة مثل [Tokyo Night (CLI)](/skins/tokyo-night-cli/) أو [Bearded Tokyo Night](/skins/bearded-tokyo-night/)، وتحقق من [دليل التوافق بين الطرفية](/blog/codex-skin-terminal-sync/) لإكمال الإعداد.
