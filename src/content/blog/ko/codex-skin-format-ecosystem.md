Codex 스킨 생태계는 아직 젊기 때문에, 파일 형식도 여전히 정착 중입니다. 현재 네 가지 형식이 공존하고 있으며, 이들 간의 호환성은 완전하지 않습니다. 각 형식을 이해하면, 사용 중인 엔진에서 읽을 수 없는 파일을 실수로 다운로드하는 일을 피할 수 있습니다.

## 네 가지 형식

| 형식 | 엔진 계열 | 로드 방식 | 이식성 |
|---|---|---|---|
| `.codedrobe-theme` | Codedrobe 스타일 갤러리 (codexskins.org) | 파일 임포트 | 중간 — 일부 엔진에서만 지원 |
| `.codextheme` | 데스크톱 관리자 (Codex Themes 데스크톱 버전) | 파일 임포트 | 중간 |
| `tmtheme` | CLI 테마 포팅 버전 (bearded, 터미널 구문 테마 등) | CLI `/theme` 명령어 | 높음 — 에디터 테마와 동일한 형식 |
| `preset` | 프롬프트 기반 엔진 (Dream Skin) | 자연어 프롬프트 | 낮음 — 엔진별 고유한 문구 해석 필요 |

## `.codedrobe-theme` — 갤러리 표준 형식

codexskins.org 같은 갤러리에서 완성된 테마 파일을 배포할 때 사용합니다. “Download .codedrobe-theme”라는 링크를 본다면, 바로 이 형식의 파일을 다운로드하게 됩니다. 일부 데스크톱 엔진에서 지원되며, 보통 한 번의 클릭으로 임포트할 수 있습니다.

**적합한 경우:** 설정 없이도 전문 디자이너가 제작한 완성도 높은 테마를 즉시 사용하려 할 때.  
**주의할 점:** 보편적인 형식이 아니므로, 사용 중인 엔진이 이 확장자를 실제로 지원하는지 반드시 확인하세요.

## `.codextheme` — 데스크톱 관리자 전용 형식

데스크톱 테마 관리자(특히 Codex Themes for desktop)에서 사용하는 형식입니다. 구조적으로는 `.codedrobe-theme`와 유사하며, 실제 사용에서는 서로 교체해 쓸 수 있는 경우도 있지만, 모든 엔진이 두 형식을 모두 수용하진 않습니다.

**적합한 경우:** 데스크톱 환경에서 테마 관리자를 설치해 사용 중인 경우.  
**주의할 점:** `.codedrobe-theme`와 확장자 이름이 비슷해 혼동하기 쉬우나, 두 형식은 반드시 호환되지 않으므로 주의가 필요합니다.

## `tmtheme` — CLI의 핵심 형식

터미널 테마 형식을 Codex CLI로 포팅한 것으로, 이 인덱스 내 [Bearded](/skins/bearded/) 포팅 버전이 가장 대표적입니다. 이 형식은 TextMate/에디터 구문 테마와 동일한 계열이며, 따라서 생태계가 매우 크고 다양합니다. tmtheme 기반의 어떤 색상 팔레트라도 포팅 스크립트를 통해 Codex CLI로 쉽게 가져올 수 있습니다.

**적합한 경우:** 가능한 한 최대의 색상 팔레트 선택지를 원하는 CLI 사용자.  
**주의할 점:** tmtheme 파일은 일반적으로 구문 강조 색상만 정의하며, 전체 UI 요소(패널, 크롬 등)를 모두 커버하지는 않습니다. 추가 설정이 필요할 수 있습니다.

## `preset` — 프롬프트 기반 형식

파일이 아닙니다. Dream Skin 같은 프롬프트 기반 엔진이 해석하는 자연어 설명입니다. 예를 들어, *“따뜻한 앰버색의 야간 테마, 채도 낮음”* 은 하나의 preset입니다. 이는 엔진 내부에 저장된 프리셋 목록에 존재합니다.

**적합한 경우:** 빠른 시도와 반복적인 조정이 필요한 경우.  
**주의할 점:** 이식성이 전혀 없습니다. 해당 프롬프트는 오직 그 프롬프트를 해석할 수 있는 특정 엔진 안에서만 의미를 가집니다.

## 형식 간 변환 방법

- **tmtheme ↔ preset:** 직접 변환 불가 — 하나는 명세(spec)이고, 다른 하나는 설명(descripton)이기 때문입니다. 팔레트를 바탕으로 프롬프트를 새로 작성해야 합니다.  
- **tmtheme → .codextheme:** 구조적으로 유사하므로, 간단한 스크립트로 자주 가능합니다. 많은 CLI 포팅 테마가 이 방식으로 시작되었습니다.  
- **codedrobe ↔ codextheme:** 경우에 따라 드롭인(drop-in) 가능 — 엔진이 두 확장자 모두를 수용한다면, 둘 다 테스트해 보세요.

일반적인 규칙: **구조화된 형식(tmtheme, codedrobe, codextheme)은 서술형 형식(preset)보다 상호 운용성이 훨씬 높습니다.** 장기간 보관할 스킨 라이브러리를 구축한다면, 구조화된 형식을 우선 선택하세요.

## 빠른 FAQ

**어느 형식이 ‘공식’ Codex 형식입니까?**  
아직 공식 형식은 없습니다. 생태계는 사용량을 통해 점차 형식을 결정하고 있으며, 현재는 tmtheme 계열 CLI 포팅이 가장 큰 동력을 얻고 있고, 프롬프트 기반 preset은 가장 많은 사용자를 확보하고 있습니다.

**결국 하나의 형식이 승리할까요?**  
아마도 구조화된 형식이 될 것입니다 — 이는 에디터 테마가 통일된 방식으로 발전한 사례와 일치합니다. 그러나 프롬프트는 사라지지 않을 것이며, “즉시 시도해 보기”라는 용도를 계속 충족시킬 것입니다.

**최대 호환성을 위해 어떤 형식을 다운로드해야 할까요?**  
CLI 친화적인 테마, 예를 들어 [Monokai Stone](/skins/monokai-stone/) 또는 [Solarized](/skins/solarized/)처럼 tmtheme/CLI 명세로 제공되는 테마를 추천합니다. 이들은 가장 광범위한 도구군에 임포트될 수 있습니다. 또한 [Tokyo Night](/skins/tokyo-night-ychampion/) 및 [Vivid Purple (CLI)](/skins/vivid-purple-cli/) 역시 널리 포팅된 강력한 선택지입니다.

**어떻게 하면 스킨이 어떤 형식을 사용하는지 알 수 있을까요?**  
이 인덱스의 모든 스킨 상세 페이지에는 설치 형식이 명시되어 있습니다 — 이것이 바로 핵심 단서입니다. 다운로드 전에 반드시 자신의 엔진과 형식을 매칭해 보세요.

형식은 기능이 아니라, 오히려 마찰입니다. 영구적인 라이브러리에는 구조화된 형식을, 탐색과 실험에는 프롬프트를 선택하세요. 그리고 각 스킨의 상세 페이지가 어떤 형식인지 알려줄 것입니다. [스킨 인덱스](/skins/)를 둘러보거나, 각 형식을 지원하는 소프트웨어를 비교한 [엔진 비교 글](/blog/codex-skin-engines-compared/)을 참고하세요.
