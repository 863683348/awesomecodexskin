이 인덱스에서 두 개의 스킨 상세 페이지를 열어보면, 서로 다른 설치 버튼을 볼 수 있습니다: 하나는 “설치 프롬프트 복사”, 다른 하나는 “테마 파일 다운로드”. 이 두 버튼은 서로 교체할 수 없으며, 그 차이는 대부분의 사람들이 생각하는 것보다 훨씬 중요합니다.

이 구분은 다음과 같습니다: **프롬프트 프리셋**(prompt presets)은 Dream Skin 같은 엔진이 해석할 수 있도록 자연어로 표현된 시각적 스타일 설명이며, **테마 파일**(theme files)은 `.codedrobe-theme`나 `.codextheme`처럼 구조화된 사양(spec)으로, 결정론적으로 로드됩니다. 각 방식에 대해 어떻게 이해해야 할지 아래에서 설명합니다.

## 프롬프트 프리셋의 작동 방식

프리셋은 하나의 문장입니다: *“Clear Glass 라이트 테마를 적용하세요 — 깔끔하고 유리처럼 투명하며 주의 산만함을 최소화한 인터페이스.”* 엔진은 이 문장을 읽고 저장된 색상 팔레트와 매칭하여 적용합니다. Dream Skin 및 유사 엔진은 이 모델 위에서 동작합니다.

**강점:**
- 현재 존재하는 가장 빠른 설치 방식 — 복사해서 붙여넣기만 하면 완료.
- 인간이 읽기 쉬움. 설명을 직접 편집해 변형된 스타일을 얻을 수 있음.
- 탐색에 탁월함: *“조금 더 따뜻하게 만들어줘”* 역시 유효한 지시입니다.

**약점:**
- 해석의 불확실성. 서로 다른 엔진이 동일한 프롬프트를 다르게 렌더링할 수 있음.
- 정밀도 부족. *“유리처럼 보이는”* 표현은 16진수 값이 아님.
- 엔진 종속성. 프롬프트를 해석할 줄 모르는 엔진에서는 해당 프리셋이 아무 의미도 없음.

## 테마 파일의 작동 방식

테마 파일은 명시적인 사양(spec)입니다: 배경, 전경, 구문 강조, 액센트 등 각 요소에 대한 정확한 16진수 값이 기재되어 있습니다. 엔진은 이 파일을 로드해, 파일에 명시된 대로 정확히 적용합니다. 갤러리 사이트(codexskins.org 등)에서 사용되는 `.codedrobe-theme`와 Codex에서 채택한 `.codextheme`가 일반적인 형식입니다.

**강점:**
- 결정론적(deterministic). 화면에 보이는 것이 바로 파일이 명시한 내용임.
- 동일한 형식을 지원하는 모든 엔진에서 이식 가능.
- 버전 관리, 차이 비교(diff), 공유가 용이 — 단순한 텍스트 파일일 뿐임.

**약점:**
- 작성 속도가 느림. 모든 값을 일일이 기술해야 함.
- 형식 분열. `.codedrobe-theme`, `.codextheme`, CLI 설정 등은 서로 호환되지 않음.
- 편집 시 형식에 대한 이해가 필요 — 단순한 문장 재구성만으로는 불가능함.

## 어느 쪽이 “더 낫나요”?

목표에 따라 달라집니다:

- **빠른 시도 및 탐색**: 프롬프트 프리셋이 우위. 5분 안에 5가지 분위기를 실험할 수 있습니다.
- **일관성 및 이식성**: 테마 파일이 우위. 동일한 파일은 어디서든 동일한 결과를 보장합니다.
- **버전 관리**: 테마 파일이 명확히 우위. 프롬프트는 자유로운 서술이고, 파일은 차이를 비교할 수 있는 명확한 사양입니다.

대부분의 사용자는 혼합 전략을 채택합니다: 먼저 프롬프트로 원하는 분위기를 찾아내고, 이후 테마 파일로 그것을 고정합니다.

## 실용적인 결정 가이드

무엇을 설치하기 전에 다음 질문을 스스로 해보세요:

1. **빠르게 시도해보고 싶다** → 프롬프트를 복사해 붙여넣기만 하면 즉시 적용.
2. **몇 달 이상 유지할 스타일을 찾았다** → 안정적이고 공유 가능한 테마 파일을 다운로드.
3. **여러 기기 또는 팀 간 동기화가 필요하다** → 테마 파일을 dotfiles 저장소에 커밋.
4. **변형을 실험 중이다** → 프롬프트를 사용하세요. *“더 따뜻하게”*는 16진수 값을 직접 수정하는 것보다 훨씬 빠릅니다.

## 자주 묻는 질문(FAQ)

**프롬프트 프리셋과 테마 파일이 동일한 외관을 생성할 수 있나요?**  
가능합니다. 프리셋 엔진의 내장 팔레트가 테마 파일의 16진수 값과 일치할 경우, 동일한 결과를 얻을 수 있습니다. 일부 엔진은 동일한 테마를 두 가지 형식 모두 제공하기도 합니다.

**엔진 업데이트에 더 잘 견디는 형식은 무엇인가요?**  
일반적으로 테마 파일입니다. 형식이 계속 지원된다면 사양(spec)은 유효성을 유지하지만, 프롬프트는 엔진이 여전히 해당 표현을 이해해야만 작동합니다.

**시작 속도 측면에서 어느 형식이 더 빠른가요?**  
차이가 미미합니다. 두 형식 모두 마이크로초 단위로 로드되는 매우 작은 설정 파일입니다.

**이 인덱스는 어떤 형식을 권장하나요?**  
각 스킨의 *설치 형식*(install format) 필드를 확인하세요 — 어떤 형식이 적용되는지 명시되어 있습니다. 예를 들어, [Monokai Stone](/skins/monokai-stone/)과 [Solarized](/skins/solarized/)는 CLI/테마 사양 형태로 제공되며, [Clear Glass](/skins/clear-glass/)와 [Vivid Purple](/skins/vivid-purple/)은 프롬프트 기반으로 최적화되어 있습니다.

한 번씩 양쪽을 직접 시도해보면, 반나절 만에 본인의 선호도를 알 수 있을 것입니다. 각 형식의 실제 예시는 [스킨 인덱스](/skins/)에서 확인하거나, 아직 아무것도 설치하지 않았다면 [설치 가이드](/blog/how-to-install-codex-skins/)부터 시작해 보세요.
