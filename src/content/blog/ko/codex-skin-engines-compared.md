Codex에 스킨을 적용하는 다섯 가지 주요 방법이 있으며, 모두 완전히 다른 방식으로 작동합니다. 잘못된 방법을 선택하면 몇 주 동안 싸우게 될 수 있습니다. 올바른 방법을 선택하면 스킨 변경은 10초 밖에 걸리지 않습니다. 이 비교 자료는 다섯 가지 방법을 한눈에 볼 수 있도록 정리하여 한 번 읽기만으로도 선택할 수 있도록 합니다.

## 다섯 가지 엔진 요약

| 엔진 | 플랫폼 | 설치 방식 | 적합한 대상 |
|---|---|---|---|
| Codex Dream Skin | macOS, Windows | 에이전트 프롬프트 / 사전 설정 | 구성 없이 사용하고 싶은 사람 |
| Codex Skin Manager | macOS, Windows | 내장 관리자 UI | 시각적 선택기를 원하는 사람 |
| ReTheme | macOS, Windows | 서명된 커뮤니티 테마 | 검증된, 정리된 테마를 원하는 사람 |
| Codex Themes CLI | 크로스 플랫폼 | CLI `/theme` 명령어 | 터미널 사용자 |
| Codepilot | 크로스 플랫폼 (npm) | 내장 TUI `/skin` | 터미널에서 생활하는 전문가 |

## Codex Dream Skin — "붙여넣기만 하면 되는" 옵션

Dream Skin(Fei-Away 프로젝트에서 개발했으며, 이 인덱스에 포함된 여러 스킨을 저술한 바 있음)은 자연언어 프롬프트를 통해 스킨을 설치합니다. "Clear Glass 라이트 테마를 적용하라"와 같은 줄을 복사하여 붙이면 엔진이 팔레트를 적용합니다. 파일을 관리하거나 명령어를 배울 필요가 없습니다.

**강점:** 새로운 모습으로 가는 가장 빠른 길; 사전 설정은 저장되어 한 번 클릭으로 기본값을 복원할 수 있습니다.
**약점:** 파일 기반 테마보다 정확도가 낮습니다 — 보이는 모습을 설명하는 것이지 특정 사양을 로드하지 않습니다.

## Codex Skin Manager — 시각적 선택기

데스크탑 관리자에 내장된 갤러리: 탐색, 미리보기, 적용, 롤백. 이는 "스킨용 앱 스토어"에 가장 가까운 것입니다. 미리보기 후 확정하기를 선호한다면 이 엔진이 당신의 선택입니다.

**강점:** 적용 전 시각적 미리보기; 비기술 사용자에게 좋습니다.
**약점:** 자신의 갤러리만 지원; 제3자 파일을 가져오기는 CLI 도구보다 더 복잡합니다.

## ReTheme — 정리된 옵션

ReTheme은 서명된 커뮤니티 테마를 배포하며, 이는 모든 테마가 제공되기 전에 검토되었음을 의미합니다. 깨진 또는 악성 파일의 위험은 낮지만, 카탈로그는 작습니다.

**강점:** 안전성과 정리; 서명된 테마는 깨끗하게 설치됩니다.
**약점:** 오픈소스 생태계보다 선택지가 적습니다.

## Codex Themes CLI — 터미널 고전

CLI 접근법(예: ychampion/codex-themes, Tokyo Night 및 Monokai Stone과 같은 테마를 포팅함)은 스킨을 패키지로 간주하고 명령어로 설치 및 전환합니다: `/theme monokai-stone`. 빠르고 스크립터블하며, dotfiles과 잘 어울립니다.

**강점:** 스크립터블; 버전 제어 가능; 다른 CLI 도구와 동일한 워크플로우.
**약점:** 내장된 시각적 미리보기 없음; 비터미널 사용자는 더 높은 진입 장벽이 있습니다.

## Codepilot — TUI 파워 툴

Codepilot(npm 설치 가능)은 `/skin` 명령어, 검증, 미리보기, 롤백, 터미널 팔레트 내보내기를 포함하는 전체 TUI 스킨 관리자를 제공합니다. 터미널 옵션 중 가장 기능이 완비된 것입니다.

**강점:** 하나의 도구에서 검증, 미리보기, 롤백 및 팔레트 내보내기; 크로스 플랫폼.
**약점:** 순수 CLI보다 더 많은 구성 요소가 있습니다; 단일 스킨만 원한다면 과잉입니다.

## 어떤 것을 선택해야 할까요?

- **빠르게 좋은 모양을 원한다면:** Dream Skin.
- **미리보기 후 확정을 선호한다면:** Codex Skin Manager.
- **검증된, 서명된 테마를 중요시한다면:** ReTheme.
- **터미널에서 생활하며 스크립터블성을 원한다면:** Codex Themes CLI.
- **완전한 파워 툴을 원한다면:** Codepilot.

다섯 가지 엔진은 이 인덱스에 있는 스킨과 호환됩니다 — 대부분의 스킨은 어떤 엔진도 소비할 수 있는 프롬프트나 테마 파일로 배포됩니다. 좋아하는 스킨부터 시작하세요, 예를 들어 [Clear Glass](/skins/clear-glass/) 또는 [Gothic Void Expedition](/skins/gothic-void-expedition/)와 같이, 그리고 당신의 작업 방식과 맞는 엔진을 선택하세요.

## 빠른 FAQ

**두 개의 엔진을 동시에 실행할 수 있습니까?**
네, 하지만 하나만 활성 관리자로 유지하세요. 두 엔진이 동시에 프리셋을 쓰면 서로 덮어씌울 수 있습니다. 하나를 주요 엔진으로 선택하고, 다른 것은 가져오기만 사용하세요.

**엔진은 모든 스킨과 작동합니까?**
항상 그렇지는 않습니다. 프롬프트 기반 엔진은 프롬프트가 필요하고, 파일 기반 엔진은 해당 파일 형식이 필요합니다. 스킨의 설치 형식 필드는 어떤 엔진이 표적으로 지정되는지를 알려줍니다.

**가장 큰 테마 라이브러리를 가진 엔진은 무엇입니까?**
오픈소스 생태계 — Dream Skin 프리셋과 CLI 포트 —는 누구나 기여할 수 있기 때문에 가장 큰 카탈로그를 가지고 있습니다. 정리된 관리자는 더 작은 그러나 더 안전한 라이브러리를 가지고 있습니다.

허황된 홍보가 아닌 작업 방식에 따라 엔진을 선택하세요. 그런 다음 [전체 스킨 인덱스](/skins/)를 둘러보세요 — 모든 스킨의 세부 페이지는 어떤 설치 형식을 사용하는지를 알려주므로, 잘못된 파일을 다운로드하는 일은 다시 없을 것입니다. 모두 처음이라면 [설치 가이드](/blog/how-to-install-codex-skins/)에서 시작하세요.
