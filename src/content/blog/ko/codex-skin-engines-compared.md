Codex에 스킨을 적용하는 주요 방법은 다섯 가지이며, 각각 완전히 다른 방식으로 작동합니다. 잘못된 방법을 선택하면 수주간 고생하게 될 수 있지만, 올바른 방법을 선택하면 단 10초 만에 스킨을 교체할 수 있습니다. 이 비교 자료는 다섯 가지 방법을 한눈에 정리해 드려서, 한 번 읽는 것으로 바로 선택하실 수 있도록 도와드립니다.

## 다섯 가지 엔진 개요

| 엔진 | 지원 플랫폼 | 설치 방식 | 가장 적합한 사용자 |
|---|---|---|---|
| Codex Dream Skin | macOS, Windows | 에이전트 프롬프트 / 사전 설정 | 설정 없이 바로 시작하고 싶은 사용자 |
| Codex Skin Manager | macOS, Windows | 내장 관리자 UI | 시각적 인터페이스로 스킨을 고르고 싶은 사용자 |
| ReTheme | macOS, Windows | 서명된 커뮤니티 스킨 | 검토 및 검증된 고품질 스킨을 원하는 사용자 |
| Codex Themes CLI | 크로스플랫폼 | CLI `/theme` 명령어 | 터미널을 주로 사용하는 사용자 |
| Codepilot | 크로스플랫폼 (npm 기반) | 내장 TUI `/skin` 명령어 | 터미널에서 모든 작업을 처리하는 고급 사용자 |

## Codex Dream Skin — “그냥 붙여넣기” 방식

Dream Skin(Fei-Away 프로젝트에서 개발했으며, 이 인덱스에 포함된 여러 스킨도 제작함)은 자연어 프롬프트를 통해 스킨을 설치합니다. 예를 들어 “Clear Glass 라이트 테마를 적용해줘”라는 문장을 복사해서 붙여넣으면, 엔진이 자동으로 색상 팔레트를 적용합니다. 관리할 파일도 없고 익숙해져야 할 명령어도 없습니다.

**장점:** 새로운 외관을 얻는 가장 빠른 경로; 사전 설정이 저장되어 있어 한 번의 클릭으로 기본값을 복원할 수 있음.  
**단점:** 파일 기반 스킨보다 정밀도가 낮음 — 구체적인 외관을 ‘설명’하는 것이지, 명세서를 ‘적재’하는 것이 아님.

## Codex Skin Manager — 시각적 선택 도구

내장 갤러리를 갖춘 데스크톱 관리자입니다: 스킨을 탐색하고, 미리 보고, 적용하고, 되돌릴 수 있습니다. 이는 ‘스킨 전용 앱 스토어’에 가장 가까운 방식입니다. 미리 보기 화면을 클릭하며 스킨을 검토한 후 결정하는 것을 선호한다면, 이것이 바로 당신을 위한 엔진입니다.

**장점:** 적용 전 시각적 미리 보기 제공; 비기술적 사용자에게 매우 친숙함.  
**단점:** 자체 갤러리에만 해당; 타사 스킨 파일을 가져오는 과정이 CLI 도구보다 덜 직관적임.

## ReTheme — 검토된 스킨 전용 옵션

ReTheme은 서명된 커뮤니티 스킨을 배포합니다. 즉, 모든 스킨이 사용자에게 도달하기 전에 검토 및 검증을 거칩니다. 이로 인해 손상되거나 악성 코드가 포함된 파일의 위험이 줄어들지만, 전체 스킨 목록은 상대적으로 작습니다.

**장점:** 안전성과 검토 체계; 서명된 스킨은 깨끗하게 설치됨.  
**단점:** 오픈소스 생태계에 비해 선택 가능한 스킨 수가 적음.

## Codex Themes CLI — 터미널의 고전적 방식

CLI 방식(예: ychampion/codex-themes처럼 Tokyo Night, Monokai Stone 등 인기 스킨을 포팅한 도구)은 스킨을 하나의 패키지처럼 취급하여, `/theme monokai-stone` 같은 명령어로 설치하고 전환합니다. 빠르고, 스크립트로 자동화 가능하며, dotfiles와도 잘 연동됩니다.

**장점:** 스크립트로 자동화 가능; 버전 관리 가능; 기존 CLI 도구들과 동일한 워크플로우 사용.  
**단점:** 내장 시각적 미리 보기 없음; 터미널을 익숙하게 사용하지 않는 사용자의 초기 진입 장벽이 높음.

## Codepilot — TUI 기반 고성능 도구

Codepilot(npm으로 설치 가능)은 `/skin` 명령어를 통한 완전한 TUI 스킨 관리 기능을 제공합니다. 검증, 미리 보기, 되돌리기, 터미널 팔레트 내보내기까지 모두 하나의 도구에서 처리할 수 있으며, 크로스플랫폼을 지원합니다. 터미널 기반 옵션 중 가장 기능이 풍부한 도구입니다.

**장점:** 검증, 미리 보기, 되돌리기, 팔레트 내보내기 기능이 통합된 단일 도구; 크로스플랫폼 지원.  
**단점:** 순수 CLI보다 구성 요소가 많음; 단 하나의 스킨만 필요하다면 지나치게 복잡할 수 있음.

## 어떤 엔진을 선택해야 할까요?

- **빠르게 멋진 외관을 원하시나요?** → Dream Skin  
- **미리 보기 화면을 클릭하며 고르는 걸 좋아하시나요?** → Codex Skin Manager  
- **검토되고 서명된 안전한 스킨을 중요하게 생각하시나요?** → ReTheme  
- **터미널에서 작업하며 자동화와 버전 관리를 원하시나요?** → Codex Themes CLI  
- **최고 수준의 기능을 갖춘 전문 도구를 원하시나요?** → Codepilot  

이 인덱스에 포함된 모든 스킨은 위 다섯 가지 엔진과 호환됩니다. 대부분의 스킨은 프롬프트 형태 또는 스킨 파일 형태로 배포되며, 어느 엔진에서도 사용할 수 있습니다. 먼저 [Clear Glass](/skins/clear-glass/)나 [Gothic Void Expedition](/skins/gothic-void-expedition/)처럼 마음에 드는 스킨을 고르신 후, 자신의 작업 방식과 가장 잘 맞는 엔진을 선택하세요.

## 간단한 FAQ

**두 개의 엔진을 동시에 실행할 수 있나요?**  
네, 가능합니다. 다만 하나를 ‘활성 관리자’로 지정해야 합니다. 두 엔진이 동시에 사전 설정을 쓰면 서로 덮어쓸 수 있으므로, 하나는 주 관리자로, 나머지는 스킨 가져오기 용도로만 사용하세요.

**모든 엔진이 모든 스킨과 호환되나요?**  
항상 그렇지는 않습니다. 프롬프트 기반 엔진은 프롬프트가 필요하고, 파일 기반 엔진은 일치하는 파일 형식이 필요합니다. 각 스킨의 상세 페이지에 있는 ‘설치 형식’ 필드를 확인하면, 어떤 엔진을 사용해야 하는지 알 수 있습니다.

**어떤 엔진이 가장 많은 스킨 라이브러리를 보유하고 있나요?**  
오픈소스 생태계 — Dream Skin의 프롬프트와 CLI 포팅 스킨 — 가 가장 큰 카탈로그를 보유하고 있습니다. 누구나 기여할 수 있기 때문입니다. 반면 검토된 관리자는 더 작지만 안전한 라이브러리를 제공합니다.

엔진은 유행이나 홍보가 아닌, 자신의 작업 방식에 따라 선택하세요. 그런 다음 [전체 스킨 인덱스](/skins/)를 탐색하세요. 모든 스킨 상세 페이지에는 사용 가능한 설치 형식이 명시되어 있으므로, 다시는 잘못된 파일을 다운로드하지 않으실 겁니다. 이 분야가 처음이신가요? [설치 가이드](/blog/how-to-install-codex-skins/)부터 시작하세요.
