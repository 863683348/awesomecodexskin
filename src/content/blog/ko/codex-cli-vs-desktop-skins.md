Codex는 두 가지 매우 다른 스킨 시스템을 가지고 있습니다: **Codex CLI 테마**와 **Codex 데스크탑 스킨**입니다. 외부에서는 비슷해 보이지만(작업 공간의 모양을 바꾸기 때문입니다), 내부적으로는 완전히 다릅니다 — 그리고 어떤 것을 선택하는지는 Codex를 어떻게 사용하는지에 달려 있습니다.

## 간단한 요약

- **Codex 데스크탑 스킨**은 *앱의 화면 구성* — 사이드바, 테두리, 표면, 강조 색상 등을 변경합니다. 풍부하고 시각적인 것이며, 프롬프트나 테마 파일을 통해 설치할 수 있습니다.
- **Codex CLI 테마**는 *터미널 색상 팔레트* — 배경, 전경 및 구문 색상을 변경합니다. 가볍고 이동성이 있으며, 명령어로 설치하고 `/theme`를 통해 적용합니다.

데스크탑 앱을 사용한다면 데스크탑 스킨을 원할 것입니다. 터미널에서 생활한다면 CLI 테마를 원할 것입니다.

## 각 시스템이 변경하는 내용

| 항목 | 데스크탑 스킨 | CLI 테마 |
|---|---|---|
| 변경 사항 | 앱의 화면 구성, 테두리, 강조 색상 | 터미널 색상 팔레트 |
| 설치 방법 | 복사-붙여넣기 프롬프트 / 테마 파일 | 설치 스크립트 + `/theme` |
| 시각적 풍부함 | 높음 (표면, 테두리) | 낮음 (색상만) |
| 이동성 | 데스크탑 엔진에 종속됨 | 어떤 터미널 팔레트와도 호환됨 |
| 되돌릴 수 있음 | 대부분의 엔진에서 한 번의 클릭으로 복원 가능 | 다른 이름으로 `/theme`를 다시 실행 |

## 당신의 작업 흐름에 맞는 것은?

**데스크탑 스킨을 선택하세요:**
- Codex 데스크탑 앱을 주 작업 공간으로 사용합니다.
- 전체 시각적 정체성을 원합니다 — 어두운 저광량, 파스텔, 네온, 애니메이션.
- 단일 클릭으로 복원 가능한 사전 설정 테마의 아이디어를 좋아합니다.

**CLI 테마를 선택하세요:**
- 주로 터미널에서 작업합니다.
- 쉘과 Codex CLI가 동일한 팔레트를 공유하길 원합니다.
- 버전 제어 가능한, 이동 가능한 설정으로 테마를 선호합니다.

## 둘 모두 사용할 수 있나요?

네 — 서로 독립적입니다. 많은 사람들이 앱용 어두운 데스크탑 스킨과 터미널용 일치하는 CLI 팔레트를 사용하여 전체 작업 공간이 하나의 시스템처럼 느껴지게 합니다. CLI 테마는 단순한 색상 팔레트이기 때문에 결합하기 쉽습니다: 두 세계 모두 존재하는 팔레트(예: Tokyo Night, Monokai Stone, Solarized)를 선택하고 모든 곳에 적용하면 됩니다.
