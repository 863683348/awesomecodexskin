我过去曾同时运行一个深色 Codex 皮肤和一套完全不同的终端配色方案。每次在两者之间切换标签页时，我的眼睛都会微微一怔——背景不同、强调色不同、整体氛围也不同。看似微不足道，但日积月累，便成了全天候的低强度干扰。

解决方法既朴素又高效：**全系统统一配色方案**。使用同一色系、相近明度、相同强调色。本页将指导你如何让终端与 Codex 皮肤采用一致的配色方案，起点正是本索引中列出的 CLI 主题。

## 为何“同步配色”优于“分别挑选两个好看的主题”

你的视觉系统天然偏好连续性。当终端、编辑器与浏览器共享相同的背景色调与强调色时，切换窗口几乎无需大脑额外处理；而一旦配色冲突，每次切换都需一次微小的视觉重定向。一天数十次切换下来，你已为毫无意义的事情消耗了真实的专注力。

第二重好处在于：截图与结对编程场景会显得协调统一。“这是同一套配置吗？”——是的，而这正是目标所在。

## 简便路径：跨平台原生支持的主题

某些配色方案已被完整移植至多种工具，因此同步近乎零成本：

- **[Tokyo Night](/skins/tokyo-night-ychampion/)** —— 原为 VS Code 主题，现亦收录于本 Codex 主题索引，并提供由 Bearded 移植的 CLI 变体，如 [Tokyo Night (CLI)](/skins/bearded-tokyo-night/)。两端均采用统一的夜蓝（night-blue）色系。
- **[Monokai Stone](/skins/monokai-stone-cli/)** —— 经典 Monokai 配色的石灰色（stone-gray）变体。广泛移植，你通常能在所用终端模拟器中轻松找到匹配的配置。
- **[Solarized](/skins/solarized-cli/)** —— 专为精确 CIELAB 明度值设计，确保跨应用渲染高度一致。它是目前最接近“处处相同”的配色方案。

任选其一，你已完成 80%：先应用 Codex 皮肤，再于终端主题选择器中启用同名配色即可。

## 手动路径：四步手动匹配法

若你钟爱的 Codex 皮肤暂无对应终端版本，则可按以下步骤手动匹配：

1. **查阅皮肤配色表**。打开该皮肤详情页——其中已列出全部颜色值。记录背景色、前景色与强调色的十六进制代码（hex）。
2. **创建终端主题文件**。主流终端模拟器（iTerm2、Windows Terminal、kitty、WezTerm）均支持基于十六进制的简易主题格式。映射规则为：背景色 → 终端背景、前景色 → 终端文字、强调色 → 终端光标/高亮色。
3. **保持明度接近**。不必严格匹配色相（hue），但终端背景明度与 Codex 背景明度差异不宜超过约 20%——否则人眼会明显感知到明暗跳跃。
4. **真实环境测试**。执行 `ls`、查看 `git log` 并用 `vim` 编辑两分钟。若背景过渡自然、毫无割裂感，即告完成。

## 何谓“足够接近”

你无需追求像素级的十六进制完全一致。只要背景属于同一色系、前景冷暖倾向一致、强调色相同——这就足够了。例如 [Monokai Stone (CLI)](/skins/monokai-stone-cli/) 与一款默认暖灰背景的标准深色终端并置，观感依然和谐。目标是视觉连续性，而非绝对一致性。

## 快速问答

**我需要同步浏览器配色吗？**  
属锦上添花，非必需项。终端 + 编辑器的组合已覆盖你绝大多数视线切换场景。若你追求极致，可一并同步浏览器开发者工具——适用相同原则。

**我的终端模拟器不支持自定义主题。**  
所有现代终端均支持。若受限于企业锁定环境，请反向操作：选择一款 Codex 皮肤，使其配色尽可能贴近你终端的 *默认* 配色方案——反向同步同样有效。

**同步配色会拖慢系统吗？**  
不会。这仅是一次性配置工作。配色方案仅涉及颜色定义，完全不影响 Codex 启动速度或运行性能。

立即选用 [Tokyo Night](/skins/tokyo-night-ychampion/) 或 [Monokai Stone](/skins/monokai-stone-cli/)，为其终端版本应用相同配色，给双眼应得的休憩。如需基础入门，可查阅完整 [皮肤索引](/skins/) 与 [Codex 皮肤安装指南](/blog/how-to-install-codex-skins/)。
