# CLI 自定义配色：绕过预设直接改色值

预设包能解决大部分需求，然后总会有一个颜色不对：注释灰在你的显示器上太暗，或者字符串的绿色跟语法主题里其他颜色打架。CLI 自定义配色解决的就是这一个具体问题。打开主题文件，改一个色值，保存，重新载入。不用装新引擎，也不用重装。这篇讲 CLI 把颜色存在哪里、每个颜色键管什么、一个改色值的完整示例、保留改动前应做的对比度检查，以及改完没反应时的排查顺序。

## CLI 把颜色存在哪儿

| 项目 | 路径 | 说明 |
| --- | --- | --- |
| 已安装主题 | `~/.codex/themes/` | 一个主题一个文件，文件名即主题名 |
| 当前启用主题 | `~/.codex/config.toml` | 记录主题名与高亮开关 |
| Shell 接线 | `~/.zshrc` / `~/.bashrc` | 由安装脚本写入，皮肤本身不碰 |
| 导出的色板 | 你自己选的存放位置 | 之后用来对齐终端配色 |

用移植脚本安装的主题会落在 `~/.codex/themes/` 下，文件名就是主题名。如果你走的是桌面端导入预设，这个文件根本不会出现在该目录里。CLI 里显示出一个你从没在命令行应用过的主题时，先确认这一点。

## 要认识的颜色键

多数 CLI 主题文件暴露的都是同一小组键名，认全它们，改色值这件事基本就不用猜了。

- `background` / `foreground`：底色与默认文字色。这两项决定了画在上面所有内容的对比度下限。
- `accent`：品牌色，用于光标、选区和面板描边。
- `comment`：次级文字。压得太低，行内注释在亮面板上就直接消失了。
- `keyword`、`string`、`function`、`number`：语法分组。多数主题只定义四到六个。
- `error`、`warning`、`success`：诊断色，也是最容易改坏的一组，因为三个颜色彼此相邻。

主题文件里没写的键会回落到 CLI 默认值，所以文件短不代表文件坏了。

## 改一个色值：完整示例

假设注释色在深色背景下太淡。打开主题文件找到这一行：

```toml
[colors]
comment = "#6b7280"
```

提到更亮一档的灰，保存：

```toml
[colors]
comment = "#8b95a5"
```

然后在 Codex CLI 里执行：

```
/theme Solarized
```

如果该主题本来就是启用状态，先切走再切回来一次。CLI 是在应用主题的那一刻读取文件，而不是持续监听文件变化。

## 保留改动之前先做对比度检查

改一个值很快，跟一个坏值相处很久。三件事大概花一分钟。

- 拿新色值和 `background` 比，别跟白色比。浅色主题上读着舒服的注释灰，换到深色主题上可能直接看不见。
- 一次只改一个键。四个颜色一起改，出了问题是说不清是哪个造成的。
- 让 `error` 和 `warning` 在色相上拉开距离。红和琥珀靠得太近，色觉障碍的读者就分不出来了。

这部分的背景知识在[高对比度皮肤：视力友好与 WCAG 参考](/blog/high-contrast-codex-skins-accessibility/)。

## 改完没反应时的排查顺序

- 改错了文件。两个主题可能共用同一个基础名。确认你编辑的是 `config.toml` 里记录的那个。
- 两个引擎写同一个文件。Dream Skin 和 CLI 移植版同时跑，最后写入的那个说了算，详见[多引擎共存：Dream Skin + CLI 同时用不打架](/blog/run-multiple-codex-skin-engines-without-conflicts/)。
- 面板没刷新。关掉窗口重开一次，先别急着重装。
- 格式漂移。引擎更新后旧主题文件可能解析不了，格式对比见 [Codex 皮肤文件格式全解](/blog/codex-skin-file-formats-explained/)。

## 常见问题

**必须直接改已安装的主题文件吗？** 可以先用新名字复制一份，原文件就保住了。CLI 读的是主题名指向的那个文件。

**能退回原始配色吗？** 删掉你那份拷贝，或者重跑一次安装脚本，两种办法都会把原文件恢复成默认值。

**改了颜色会影响我其他皮肤吗？** 不会。颜色按主题文件逐个读取，改一个主题不影响皮肤库里的其他条目。

**Windows 上也一样操作吗？** 路径不同，键名一致。Windows 的主题目录在 `%USERPROFILE%\.codex\themes\`。
