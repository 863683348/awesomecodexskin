# 深浅双修：白天和夜里各配一套 Codex 皮肤

多数人挑定一套 Codex 皮肤就整年不换。我以前也这样，直到发现同一套配色中午看着还行，半夜就扎眼。挑最好的浅色加深色 Codex 皮肤，思路不是找一个神奇的中庸配色，而是承认你的工位会变，一套颜色伺候不了两种光线。

下午两点，窗户在你背后，屏幕一片发白，深底浅字直接糊进反光里。凌晨一点，房间暗下来，瞳孔放大了，同一套深色皮肤又开始把满饱和的青色关键字往你眼睛里灌。把亮度调低，这两个问题一个都解决不了。

## 为什么一套皮肤撑不过一整天

可读性说的是配色和房间之间的关系，不是配色自己的属性。WCAG 的对比度数值是在固定显示器、固定环境里测出来的，所以纯白配纯黑能测出 21:1，每项检查都过，凌晨两点照样看得眼睛发酸。

浅色配色在另一头失效。日光灯下读起来很舒服的一套高亮配色，房间一暗，就变成一盏正对着脸的灯。我试过让系统主题自动切换，编辑器每次都跟得不干净。两套皮肤加一条命令，反而少折腾。

## Codex 深浅双皮肤设置到底怎么跑

所谓 Codex 深浅双皮肤设置，就是装两套，再定个什么时候用哪套的规矩。Codex 只存一个生效预设，应用第二套会覆盖这个位置。没有合并，配置里也不会攒下残骸。

```
codex-theme apply clear-glass
codex-theme apply gothic-void-expedition
```

早上跑第一条，天黑了跑第二条。想让机器自己干，把两行塞进一个 shell 别名或者定时任务就行。CLI 版本用同一条命令，所以下面的暖色搭配里放的是 `amber-nocturne`。

定下来之前有一件事要查：选浅色和深色两半时，尽量让它们的语法高亮用同一套颜色逻辑。如果一边把字符串标成绿色、另一边标成品红，那每次切完的头十分钟，你都在重读自己刚写的代码。

## 四组值得装的浅色深色皮肤组合

下面都是索引里真实存在的条目，四组我都在不同时期装过。表故意做得很短，每一组浅色深色皮肤组合解决的是同一个日夜问题的不同版本。

| 搭配 | 浅色那一半 | 深色那一半 | 适合 |
| --- | --- | --- | --- |
| 默认工位 | `clear-glass` | `gothic-void-expedition` | 白天办公室，接深夜 |
| 全天暖色 | `berry-light-journal` | `amber-nocturne` | 嫌蓝灰冷的人 |
| 由柔入深 | `berry-light-journal` | `mythic-guardian-noir` | 长时间写东西，装饰要少 |
| 极简 | `clear-glass` | `monokai-stone` | 一切从终端出发的工作流 |

`clear-glass` 配 `gothic-void-expedition` 是我会直接塞给新手的一组。浅色那半不抢戏，深色那半用的是近黑的藏青而不是纯黑，前景文字不会发飘。它也是库里安装量最高的一款，你基本不会撞上一个没人试过的预设。

暖色那组是给不喜欢蓝灰的人。`amber-nocturne` 跑在 CLI 上，底色是 #3B2F1E，一种深到看着像黑的棕，直到旁边落下一块暖色高亮才显出来。拿它和 `berry-light-journal` 配，两半像是同一张桌子在不同钟点。

## 日夜切换 Codex 皮肤时别把自己切丢

切换本身只有一条命令，但有几个习惯能让日夜切换 Codex 皮肤没那么烦人。

1. 在换任务之前切，别切到一半。函数写到中间是最不适合重新认屏幕的时刻。
2. 把两条命令放进同一个别名，省得每次还要记哪个 slug 是哪个。
3. 切完看一眼 diff 视图。颜色分工在那里比在主编辑器里更要紧。
4. 用了暖色深色皮肤就别再开系统的蓝光过滤。两层暖色叠起来会把所有东西推成橙色，语法高亮的色彩准确度也跟着没了。

写个小脚本按点执行、让它替你切换，也行，只是我一直没弄。如果某一半突然不生效，先重跑命令，别急着重装。引擎在应用时写入生效预设，缓存旧了比皮肤坏了常见得多。

## 关于同时用两套皮肤，常被问到的几件事

### 只在夜里写代码，也值得这么折腾吗？

多半不值得。挑一套深色，把前景饱和度压下去，然后就别再想这事了。只有当你的环境会变，这套搭配才回本。

### 能把 CLI 皮肤当浅色那一半用吗？

可以，但先看皮肤卡片上的平台字段。`amber-nocturne` 在索引里有桌面版和 CLI 版两个条目，是分开的。应用错了的那一个，上一个预设还留在那儿生效。

### 这几组覆盖了所有分类吗？

没有。索引里 103 款皮肤分在八个精选分类下，这四组只是我反复会回去用的。如果你整天在终端里，或者整天在截屏，去翻完整列表更合适。
