Codex には、2 つの非常に異なるスキンシステムがあります：**Codex CLI テーマ**と**Codex Desktop スキン**です。見た目は似ています（どちらもワークスペースの外観を変更します）が、内部の仕組みはまったく異なります。適切な方を選ぶかどうかは、Codex をどのように利用しているかに依存します。

## 要約

- **Codex Desktop スキン**は、*アプリケーションの UI エレメント*（サイドバー、境界線、サーフェス、アクセントカラーなど）を変更します。視覚的に豊かで、インストールはポップアップによる入力またはテーマファイルの読み込みで行います。
- **Codex CLI テーマ**は、*ターミナルのカラーパレット*（背景色、文字色、構文ハイライト色など）を変更します。軽量で移植性が高く、コマンドによるインストールと `/theme` コマンドによる適用を行います。

デスクトップアプリをご利用の場合は、Desktop スキンをお選びください。一方、ターミナル中心で作業される場合は、CLI テーマが適しています。

## 各システムが変更する要素

| 項目 | Desktop スキン | CLI テーマ |
|---|---|---|
| 変更対象 | アプリケーションの UI エレメント（境界線、サーフェス、アクセントカラーなど） | ターミナルのカラーパレット |
| インストール方法 | コピー＆ペーストによるポップアップ入力／テーマファイルの読み込み | インストールスクリプト＋`/theme` コマンド |
| 視覚的豊かさ | 高い（サーフェスや境界線を含む） | 低い（カラーパレットのみ） |
| 移植性 | Desktop エンジンに依存 | 任意のターミナルのカラーパレットと互換 |
| 元に戻す容易さ | ほとんどのエンジンでワンクリック復元可能 | 別の名前で `/theme` を再実行 |

## あなたのワークフローに合うのはどちら？

**Desktop スキンを選択すべきケース：**
- Codex Desktop アプリをメインの作業環境として利用している。
- 暗めのローライトモード、パステル調、ネオン、アニメ風など、完全なビジュアルアイデンティティを求める。
- ワンクリックで簡単に元に戻せる事前設定済みテーマを好む。

**CLI テーマを選択すべきケース：**
- 主にターミナル上で作業している。
- シェルと Codex CLI で同じカラーパレットを共有したい。
- テーマをバージョン管理可能・移植性の高い設定として扱いたい。

## 両方を併用できますか？

はい。両者は独立しており、併用可能です。多くのユーザーは、アプリには暗めの Desktop スキンを、ターミナルにはそれにマッチした CLI パレットを適用し、全体として統一感のあるワークスペースを構築しています。CLI テーマは単なるカラーパレットであるため、組み合わせは簡単です：両方の世界で提供されているパレット（例：Tokyo Night、Monokai Stone、Solarized）を選んで、すべての場所に適用すればよいのです。
