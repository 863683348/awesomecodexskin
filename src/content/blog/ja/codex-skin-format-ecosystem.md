Codex スキンの世界はまだ黎明期にあり、そのためフォーマットもまだ定まっていません。現時点では4種類のフォーマットが存在し、互換性も完全ではありません。これらのフォーマットを理解しておくことで、ご自身のエンジンが読み込めないファイルをダウンロードしてしまうリスクを回避できます。

## 4つのフォーマット

| フォーマット | エンジンファミリー | 読み込み方式 | 移植性 |
|---|---|---|---|
| `.codedrobe-theme` | Codedrobe スタイルのギャラリー（codexskins.org） | ファイルインポート | 中程度 — 少数のエンジンのみ対応 |
| `.codextheme` | デスクトップマネージャー（Codex Themes for desktop） | ファイルインポート | 中程度 |
| `tmtheme` | CLI 向けテーマ移植版（Bearded、ターミナル構文テーマなど） | CLI `/theme` コマンド | 高い — エディタ用テーマと同一フォーマット |
| `preset` | プロンプトエンジン（Dream Skin） | 自然言語によるプロンプト | 低い — エンジン固有の表現に依存 |

## `.codedrobe-theme` — ギャラリースタンダード

codexskins.org などのギャラリーで、完成済みテーマファイルを配布する際に使用されるフォーマットです。「.codedrobe-theme をダウンロード」と表示されている場合、これが該当します。一部のデスクトップエンジンでサポートされており、通常はワンクリックでインポート可能です。

**推奨用途：** 設定作業なしで、デザイナーが制作した洗練されたテーマをすぐに利用したい場合。  
**注意点：** 汎用的ではありません — ご自身のエンジンがこの拡張子を正しく読み込めるか、事前に確認してください。

## `.codextheme` — デスクトップマネージャー向けフォーマット

デスクトップテーママネージャー（特に Codex Themes for desktop）で採用されているフォーマットです。構造的には `.codedrobe-theme` と類似しており、実際には互換性がある場合もありますが、すべてのエンジンが両方をサポートしているわけではありません。

**推奨用途：** デスクトップ環境でマネージャーを既に導入済みのユーザー。  
**注意点：** `.codedrobe-theme` との名称が似ており混同されやすいですが、拡張子が同じでも互換性は保証されません。

## `tmtheme` — CLI の主力フォーマット

ターミナルテーマとして開発されたフォーマットを Codex CLI に移植したもの（本インデックスにおける Bearded 移植版が最も明確な例です）。これは TextMate／エディタ構文テーマと同じフォーマットファミリーであり、エコシステムが非常に充実しています — tmtheme 形式のカラーパレットであれば、移植スクリプトを用いることで Codex CLI へ容易に取り込むことができます。

**推奨用途：** 最大限のカラーパレット選択肢を求める CLI ユーザー。  
**注意点：** `tmtheme` ファイルは構文色を定義するものであり、UI 全体（パネルやウィンドウ装飾など）を網羅しているとは限りません。追加設定が必要になる場合があります。

## `preset` — プロンプト形式

ファイルではありません。Dream Skin などのプロンプトエンジンが解釈する自然言語による記述です。「暖かみのあるアンバー系ナイトテーマ、彩度を低く」のような記述が preset に該当します。これはエンジン内部の保存済み preset リストに格納されます。

**推奨用途：** 素早い試行・反復的な調整。  
**注意点：** 移植性はゼロです。その preset は、その特定の表現を理解できるエンジン内でのみ意味を持ちます。

## フォーマット間の変換方法

- **tmtheme ↔ preset：** 直接変換は不可能です — 一方は仕様書、他方は説明文です。パレットから新たに自然言語による記述を書き直す必要があります。  
- **tmtheme → .codextheme：** 両者とも構造化されたカラースペックであるため、小さなスクリプトで変換可能な場合が多く、多くの CLI 移植版はこの経路で始まっています。  
- **codedrobe ↔ codextheme：** 実際に置き換え可能であることも多いですが、エンジンがどちらの拡張子も受け付ける場合は、両方を試して動作確認することをおすすめします。

一般的な原則として：**構造化フォーマット（tmtheme、codedrobe、codextheme）は、自然言語フォーマット（preset）よりも相互運用性が高い**です。長期間使い続けるスキンライブラリを構築する際は、構造化フォーマットを優先しましょう。

## よくある質問（Quick FAQ）

**「公式」Codex フォーマットはどれですか？**  
現時点では存在しません。エコシステムは実際の利用状況によって徐々に収束しつつあります — 現在のところ、tmtheme ファミリーの CLI 移植版が最も勢いがあり、一方で prompt preset はユーザー数が最も多い状況です。

**いずれかのフォーマットが将来的に標準となるでしょうか？**  
おそらく構造化フォーマットが主流になるでしょう — エディタテーマの歴史がそう示しています。ただし、prompt は消えることはなく、「すぐに試したい」というニーズに応える重要な役割を果たし続けます。

**最大限の互換性を確保するために、どのフォーマットをダウンロードすべきですか？**  
tmtheme／CLI スペックとして提供される CLI 向けテーマ、たとえば [Monokai Stone](/skins/monokai-stone/) や [Solarized](/skins/solarized/) が最も広範なツール群に対応します。また、[Tokyo Night](/skins/tokyo-night-ychampion/) や [Vivid Purple (CLI)](/skins/vivid-purple-cli/) も、幅広く移植された信頼性の高い選択肢です。

**スキンがどのフォーマットに対応しているかをどう確認すればよいですか？**  
本インデックス内の各スキン詳細ページには、インストール可能なフォーマットが明記されています — それが判断の決め手です。ダウンロード前に、ご自身のエンジンがそのフォーマットに対応しているか必ず確認してください。

フォーマットは機能ではなく、むしろ障壁（friction）です。永続的に使うライブラリには構造化フォーマットを、探索・試行には prompt を選びましょう。そして、各スキンの詳細ページが、あなたが扱っているフォーマットを正確に教えてくれます。[スキンインデックス](/skins/) を閲覧するか、あるいは各フォーマットに対応するソフトウェアを比較した [エンジン比較記事](/blog/codex-skin-engines-compared/) もご覧ください。
