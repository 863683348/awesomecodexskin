デスクトップ版 Codex のスキンを適用する場合、おそらく以下の2つの名前を耳にしたことがあるでしょう：**Codex Dream Skin** と **Codex Skin Manager**。これらは最も人気のあるデスクトップ向けスキンエンジンであり、同じ目的（スキンの適用）に対して正反対のアプローチを採用しています。一方は「自分が望むものをテキストで入力」し、他方は「ギャラリーから視覚的に選択」します。以下に、両者の詳細な比較を示します。

## 核心的な違い

| | Dream Skin | Codex Skin Manager |
|---|---|---|
| インストール方式 | 自然言語によるプロンプト／プリセット | ビジュアルピッカー＋内蔵ギャラリー |
| 対応プラットフォーム | macOS、Windows | macOS、Windows |
| オープンソース | はい（Fei-Away/Codex-Dream-Skin） | はい（hyhang915/Codex-Skin-Manager） |
| プリセットライブラリ | 大規模・コミュニティ主導のプリセット群 | 精選されたギャラリー＋手動インポート機能あり |
| 学習コスト | ほぼゼロ | ほぼゼロ |
| 精度 | 中程度（自然言語を解釈） | 高い（正確なファイルを適用） |

## Dream Skin：プロンプト駆動型エンジン

Dream Skin では、スキン適用を「会話」として扱います。希望する外観を記述したプロンプトをペーストまたは入力すると、それに合致するプリセットが自動的に適用されます。本インデックスで見かける「プロンプトベースのインストールボタン」の多くは、このエンジンによって実現されています。

**強み：**
- **スピード。** 新しい外観を試すには、ただコピー＆ペーストするだけ。5分で5種類のスキンを試すことも十分可能です。
- **自然な反復的調整。** 「もっと暖色系にして」「コントラストを高めて」など、日常的な表現そのものが有効なコマンドになります。
- **コミュニティによるプリセット。** Fei-Away リポジトリには大規模かつ活発なプリセットライブラリがあり、本インデックスに掲載されているいくつかのスキンも同リポジトリが提供しています。

**課題点：**
- **解釈のばらつき。** 同じプロンプトでも、バージョンによってわずかに異なる結果が出ることがあります。
- **決定論的でない。** 「記述」しているだけで、「厳密な指定」は行っていません。

## Codex Skin Manager：ビジュアル駆動型エンジン

Skin Manager は「アプリストア方式」を採用しており、スキンを閲覧・プレビュー・適用・ロールバックできるUIを提供します。プロンプトも構文も不要——クリックするだけです。

**強み：**
- **適用前のビジュアルプレビュー。** 実際に適用する前に、スキンの見た目を確認できます。
- **正確な適用。** テーマファイルは、指定通りに正確に適用されます。
- **初心者にもやさしい。** 特に学ぶ必要はなく、ギャラリーがすべてを説明してくれます。

**課題点：**
- **ギャラリーへの依存。** 手動でファイルをインポートしない限り、カタログに登録されているものに限定されます。
- **探索がやや遅い。** プロンプトをペーストするより、プレビューをクリックしながら進める方が時間がかかります。

## 実際のワークフロー比較

- **気分に合わせて素早く試したいとき：** Dream Skin が優勢。「夜空のような青を基調としたターミナルテーマを見せて」と一言でOK。
- **完成度の高い外観を最終的に採用したいとき：** Skin Manager が優勢。プレビューしてから適用すれば、期待通りの結果が得られます。
- **自分専用のスキンライブラリを管理したいとき：** Skin Manager が優勢——ギャラリー形式のライブラリ表示は、プロンプトが並ぶフォルダよりも使い勝手が良いからです。
- **スクリプトや dotfiles を使った自動化：** どちらも本来の強みではありません——これは CLI の領域です。ただし、Dream Skin のプリセットはテキストとして読みやすく、多少はスクリプトとの親和性があります。

## どちらをインストールすべきか？

**Dream Skin を選ぶべき場合：** 探索を楽しみたい、ファイルより「説明文」を信用したい、そして最大規模のコミュニティ製プリセットライブラリを使いたいとき。

**Codex Skin Manager を選ぶべき場合：** 「適用前に見てから決めたい」、ギャラリー形式のUIが好み、そして正確なファイル単位での適用を重視するとき。

**両方をインストールしてもよい場合：** スペースに余裕があるなら、ぜひそうしてください。多くのユーザーは、Dream Skin で幅広く探索し、Skin Manager で「お気に入り」を厳選・管理しています。両者は、片方を「主要な適用ツール」として設定しておけば、互いに干渉しません。

## よくある質問（Quick FAQ）

**両者はプリセットを共有できますか？**  
標準ではできません。Dream Skin はプロンプトベースのプリセットを、Skin Manager はテーマファイルを扱います。たとえば [Gothic Void Expedition](/skins/gothic-void-expedition/) のようなスキンは、両方のインストール方法に対応した手順が用意されていることがあります。

**どちらがコミュニティサポートが充実していますか？**  
Dream Skin のプリセットリポジトリは規模が大きく、歴史も古い一方、Skin Manager は新しいですが活発に開発・メンテナンスされています。本稿執筆時点では、いずれも継続的にメンテナンスされています。

**両者が競合することはあるでしょうか？**  
両方を「アクティブな適用ツール」として設定した場合のみ、競合が発生します——後から起動した方が優先されます。必ず片方を「主要な適用ツール」として指定してください。

**どちらが速いですか？**  
起動時間の差はほとんどありません。ただし、適用速度には差があり、プロンプトのペーストはギャラリーからのクリックより明らかに高速です。
