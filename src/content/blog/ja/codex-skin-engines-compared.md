Codex にスキンを適用するには、主流の方法が5つあります。これらはそれぞれまったく異なる仕組みで動作します。間違った方法を選ぶと、数週間にわたり苦戦することになります。一方、正しい方法を選べば、スキン変更はわずか10秒で完了します。この比較表では、5つの方法を並べて一目で見られるようにし、読むだけで最適な選択ができるようになっています。

## 5つのエンジン：概要

| エンジン | 対応プラットフォーム | インストール方式 | 最適なユーザー層 |
|---|---|---|---|
| Codex Dream Skin | macOS、Windows | エージェントによるプロンプト／プリセット | 設定ゼロで始めたい人 |
| Codex Skin Manager | macOS、Windows | 組み込みのマネージャーUI | ビジュアルでテーマを選択したい人 |
| ReTheme | macOS、Windows | 署名付きコミュニティテーマ | 厳選・検証済みのテーマを重視する人 |
| Codex Themes CLI | クロスプラットフォーム | CLI の `/theme` コマンド | ターミナル中心のユーザー |
| Codepilot | クロスプラットフォーム（npm） | 組み込みTUIの `/skin` コマンド | ターミナルで高度な操作をしたいパワーユーザー |

## Codex Dream Skin — 「ただペーストするだけ」オプション

Dream Skin（Fei-Awayプロジェクトによるもの。本インデックスに掲載されているいくつかのスキンも同プロジェクトが制作）は、自然言語によるプロンプトからスキンをインストールします。たとえば「Clear Glass light theme を適用」という一文をコピーしてペーストするだけで、エンジンが自動的にカラーパレットを適用します。管理すべきファイルもなければ、覚えるコマンドもありません。

**強み：** 新しい外観を得るまでの最速ルート；プリセットは保存されるため、ワンクリックでデフォルト設定を復元可能。
**弱み：** ファイルベースのテーマより精度がやや劣る——見た目を「説明」しているだけで、厳密な仕様を「読み込む」わけではない。

## Codex Skin Manager — ビジュアルピッカー

内蔵ギャラリーを備えたデスクトップ用マネージャーです。閲覧・プレビュー・適用・ロールバックが可能です。「スキン専用アプリストア」に最も近い体験を提供します。コミットする前にプレビューをクリックして確認するのが好きな方には、まさにこのエンジンがぴったりです。

**強み：** 適用前にビジュアルプレビューが可能；非技術系ユーザーにも使いやすい。
**弱み：** 自身のギャラリーに収録されたテーマのみ対応；サードパーティ製ファイルのインポートはCLIツールに比べるとやや煩雑。

## ReTheme — 厳選されたオプション

ReThemeは署名付きのコミュニティテーマを配布しており、すべてのテーマがユーザーに届く前にレビューを経ています。その結果、壊れたファイルや悪意あるファイルのリスクが低減しますが、カタログの規模はやや小さくなります。

**強み：** 安全性と厳選性；署名付きテーマはクリーンにインストール可能。
**弱み：** オープンソースエコシステムに比べ、選択肢が少ない。

## Codex Themes CLI — ターミナルの定番手法

CLI方式（例：ychampion/codex-themes など。Tokyo Night や Monokai Stone などのテーマを移植）では、スキンを「パッケージ」として扱い、`/theme monokai-stone` のようなコマンドでインストール・切り替えを行います。高速かつスクリプト化可能であり、dotfilesとの連携も容易です。

**強み：** スクリプト化可能；バージョン管理可能；他のCLIツールと同じワークフローで利用可能。
**弱み：** 組み込みのビジュアルプレビューなし；ターミナルに慣れていないユーザーにとっては導入ハードルが高い。

## Codepilot — TUIによるパワーツール

Codepilot（npmでインストール可能）は、`/skin` コマンドを備えた完全なTUIスキンマネージャーです。検証機能、プレビュー、ロールバックに加え、ターミナルのカラーパレット出力もサポート。ターミナル向けオプションの中では、最も機能が充実しています。

**強み：** 検証・プレビュー・ロールバック・パレット出力が1つのツールで完結；クロスプラットフォーム対応。
**弱み：** 単純なCLIよりも構成要素が多く、1つのスキンしか使わない場合には過剰な機能となる可能性がある。

## どれを選ぶべきか？

- **すぐに素敵な外観が欲しい：** Dream Skin  
- **プレビューをクリックして選びたい：** Codex Skin Manager  
- **検証済み・署名付きのテーマを重視する：** ReTheme  
- **ターミナル中心で、スクリプト化を重視する：** Codex Themes CLI  
- **フルパワーのツールが欲しい：** Codepilot  

本インデックスに掲載されているすべてのスキンは、上記5つのエンジンと互換性があります。ほとんどのスキンは、いずれかのエンジンが処理可能なプロンプトまたはテーマファイルの形式で配布されています。まずお気に入りのスキン、たとえば [Clear Glass](/skins/clear-glass/) や [Gothic Void Expedition](/skins/gothic-void-expedition/) から始めて、ご自身の作業スタイルに合ったエンジンをお選びください。

## よくある質問（Quick FAQ）

**2つのエンジンを同時に実行できますか？**  
はい、可能です。ただし、アクティブなマネージャーは1つに絞ってください。2つのエンジンが同時にプリセットを書き込むと、互いに上書きしてしまうことがあります。メインのエンジンを1つ決め、他のエンジンはインポート専用としてご利用ください。

**すべてのエンジンがすべてのスキンに対応していますか？**  
必ずしもそうではありません。プロンプトベースのエンジンはプロンプトを必要とし、ファイルベースのエンジンは対応するファイル形式を必要とします。各スキンの詳細ページにある「インストール形式」欄で、対応エンジンをご確認いただけます。

**どのエンジンが最も多くのテーマを提供していますか？**  
オープンソースエコシステム——Dream SkinのプリセットやCLI版テーマ——が最大のカタログを誇ります。誰でも貢献できるため、規模が大きいのです。一方、厳選型マネージャーは、安全性を優先する代わりに、カタログ規模はやや小規模です。

流行や話題ではなく、「ご自身のワークフロー」に基づいてエンジンを選んでください。その後、[完全なスキンインデックス](/skins/) をご覧ください。各スキンの詳細ページには、使用可能なインストール形式が明記されているため、今後二度と間違ったファイルをダウンロードすることはありません。初めての方は、まずは [インストールガイド](/blog/how-to-install-codex-skins/) をご覧ください。
