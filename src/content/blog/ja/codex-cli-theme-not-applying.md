`/theme` が何も返さない、色が変化しない、またはパレットの表示が正しくない場合 — Codex CLI のテーマ関連の問題は、ほぼ常に以下の5つの原因のいずれかに起因します。以下に、それぞれの原因を順に診断・修正する方法を示します。

## 1. テーマがインストールされていない（最も一般的）

`/theme` コマンドは、Codex CLI のテーマディレクトリ内に実際に存在するテーマのみを一覧表示します。インストールスクリプトを一度も実行していない場合、リストは空になるか、デフォルトテーマのみが表示されます。

**修正方法：** まずパレットをインストールしてください。

```bash
curl -fsSL https://raw.githubusercontent.com/vufly/bearded-theme-ports/master/scripts/install-codex.sh | sh
```

その後、プロンプトを再起動してから `/theme` を再度実行してください。新しいパレットが、その正確な名前で表示されるはずです。

## 2. 起動時のカラーキャッシュが古くなっている

一部のポートでは、Codex CLI 起動時に色がキャッシュされます。テーマを適用した直後は、次回の起動までパレットが正しく表示されないことがあります。

**修正方法：** テーマを適用した後に Codex CLI を再起動し、同じ名前で `/theme` を再実行してください。正しいパレットが表示された場合は、キャッシュが原因だったということです。

## 3. テーマ名が一致していない

`/theme` はテーマ名を**完全一致**で照合します。たとえば `Tokyo Night` は `tokyo-night` や `TokyoNight` とは異なります。

**修正方法：** 引数なしで `/theme` を実行し、表示された一覧から**正確な名前をコピー**して、そのまま適用してください。

## 4. 不完全または誤ったパレットファイル

移植スクリプトからコピーしたパレットファイルが不完全である場合があります（例：背景色、文字色、構文ハイライト用のキーが欠落している）。この場合、ほとんどデフォルトの色のまま、ごく一部だけが変更されるといった現象が起こります。

**修正方法：** 完全なテーマを再取得するためにインストールスクリプトを再実行するか、マネージャーを使ってファイルの妥当性を検証してください：

```bash
# Codex Themes CLI は適用前にパレットの妥当性を検証します：
codex-theme validate <name>
codex-theme apply <name>
```

## 5. ターミナルと CLI の設定が同期していない

*ターミナル* の見た目は正しくても Codex CLI の表示が異なる（あるいはその逆）場合、両者が異なる設定を読み込んでいることを意味します。CLI のテーマは単なるカラーパレットであり、ターミナルのプロファイルを変更しません。

**修正方法：** 同じパレットを両方に適用して同期させます。Codex Themes CLI は、同一の色をターミナルプロファイルにも書き込むことができます。これにより、1 回の適用で両方の表示を同時に更新できます：

```bash
codex-theme export <name> --to-terminal
```

## それでも解決しない場合？

クリーンな状態に戻すために、以下の手順を実行してください：  
パレットをアンインストール → Codex CLI を再起動 → 再度インストール → 正確な名前で適用  

特定のスキンに問題がある場合は、最新のパレットバリエーションを確認するために [Mono & Terminal カテゴリ](/skins/category/mono-terminal/) を参照するか、完全なインストール手順については [CLI themes ガイド](/blog/codex-cli-themes-guide/) をご覧ください。
